# BeeAI Investment Analyst

**A two-agent investment-planning workbench that combines specialist handoff, deterministic SIP projections, human feedback, and Pydantic-validated JSON.**

## Overview

The workbench collects an investor's age, income, risk preference, monthly SIP contribution, and time horizon. A BeeAI Coordinator `ReActAgent` can invoke a wrapped Risk Specialist agent, which uses risk-profiling and local asset-dictionary tools. The coordinator also has access to a SIP calculator. The user can edit/refine a text draft, then approve it for parsing into a Pydantic `InvestmentPlan` and download JSON.

## Workflow and tool roles

```text
Investor inputs -> Coordinator ReActAgent
                   ├─ ConsultRiskSpecialist tool -> Risk Specialist ReActAgent
                   │                               ├─ RiskProfilerTool
                   │                               └─ AssetDictionaryTool
                   └─ SIPCalculatorTool
                 -> editable draft -> user feedback/refinement
                 -> parse + Pydantic validation -> JSON -> download
```

| Tool/schema | Role |
|---|---|
| `SIPCalculatorTool` | Computes a future-value estimate from monthly contribution, assumed annual rate, and years. |
| `AssetDictionaryTool` | Filters a local JSON asset list by risk label. |
| `RiskProfilerTool` | Applies the coded rule that age over 60 with a high-risk preference is downgraded to medium. |
| `ConsultRiskSpecialistTool` | Runs the specialist agent and returns its final text to the coordinator. |
| `InvestmentPlan` | Requires investor risk profile, allocations, allocation total, projected value, and disclaimer; its validator checks that allocation percentages total exactly 100. |

## Implementation details and assumptions

- The configured primary model is `openai:gpt-4.1-mini`; initialization code has a `gpt-3.5-turbo` fallback if model construction raises an exception.
- The source does not explicitly configure model temperature; do not assume end-to-end deterministic generation.
- SIP projection uses an assumed 12% annual rate in the UI flow. The rate is a scenario assumption, not a forecast or promised return.
- `asset_dictionary.json` is generated by an early notebook cell from a hard-coded dictionary; it is not listed as a committed project file.
- The output schema checks the allocation sum, but schema validity is not evidence of financial suitability or numeric realism.
- The session store is an in-memory Python dictionary and does not persist across restarts.

## Run in Google Colab

The checked-in script contains `!pip` and `google.colab.userdata`; run it as notebook code rather than as an unchanged local Python script.

1. Add `OPENAI_API_KEY` to Colab Secrets and grant notebook access.
2. Run the dependency-installation cell:

   ```bash
   pip install beeai-framework openai pydantic gradio
   ```

3. Execute the cells in order so `asset_dictionary.json` is created, agents and tools initialize, and the Gradio workbench launches.
4. Enter the investor profile, generate a draft, optionally provide feedback, approve/finalize, and export the JSON result.

## Limitations and security

- No live market prices, financial statements, or market-data feed is used.
- Asset choices and return ranges come from a small local example dictionary.
- The age/risk rule is a simplified hard-coded heuristic, not a regulated suitability framework.
- SIP calculations depend on the assumed rate and formula; they do not model taxes, fees, inflation, volatility, or contribution changes.
- The plan is generated in natural language before parsing; the parser and repair attempts can fail or misinterpret an unusual draft.
- Do not provide real account data or personally identifiable financial data to a third-party model without appropriate authorization.
